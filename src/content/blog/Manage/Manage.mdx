```bash
java -jar rmg-5.1.0-jar-with-dependencies.jar enum 10.129.29.138 2222
```

NO estás “lanzando un exploit”. Estás haciendo esto:
> “Voy a hablar con un **servicio Java remoto** usando **el protocolo RMI**,  
> y voy a preguntarle **qué objetos Java remotos existen y cómo están configurados**.”

En Java, cuando una aplicación quiere exponer objetos remotamente:
1. Arranca un **RMI Registry**
2. Registra objetos con un **nombre**
3. Los clientes preguntan:
    > “¿Qué nombres tienes?”
4. El registry responde con **referencias a objetos Java**

Analogía perfecta:

| Mundo real        | Java         |     |
| ----------------- | ------------ | --- |
| DNS               | RMI Registry |     |
| Nombre de dominio | Nombre RMI   |     |
| IP/puerto         | Stub remoto  |     | 

El subcomando `enum` hace **una batería de pruebas ordenadas**, todas con la misma idea:
> “Dime QUÉ expones y CÓMO lo expones”

RMG se conecta a:

```
10.129.29.138:2222
```

Y dice, literalmente (a nivel de protocolo):

> “Hola, soy un cliente RMI.  
> Dame la lista de nombres registrados.”

Si esto falla → no hay nada que hacer.  
Si funciona → **hay Java remoto expuesto**.

El registry responde:

```
jmxrmi
```

 `jmxrmi` es **estándar oficial de JMX**
Se sabe porque **JMX siempre se registra así por defecto**.

📌 En este punto ya sabes:

> “Esta aplicación Java expone su interfaz de administración”

Cuando RMG ve `jmxrmi`, hace lo siguiente:

> “Vale, dame el objeto Java asociado a ese nombre”

El registry responde con un **stub**:

```
javax.management.remote.rmi.RMIServerImpl_Stub
```

Esto significa:
- No es un objeto cualquiera
- Es la **implementación oficial del servidor JMX**
- Es el punto de entrada a **toda la gestión remota**

Después de ejecutar ese comando, deberías pensar algo como:

> “He descubierto un servicio Java  
> que expone su interfaz de administración (JMX)  
> sobre RMI, sin autenticación aparente  
> y sin sandbox.
> 
> El RMI en sí está parcheado,  
> pero JMX sigue siendo una superficie enorme.”

Eso es **pensar como pentester**, no como usuario de herramientas.
